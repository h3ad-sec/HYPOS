# HYPOS — Claude Code Context

## What this project is

HYPOS is a browser-based hypothesis-driven threat hunting platform built for the **H3AD-SEC** portfolio.

- **Portfolio:** https://h3ad-sec.github.io
- **Project repo:** github.com/h3ad-sec/HYPOS
- **GitHub Pages:** h3ad-sec.github.io/HYPOS/
- **Parent module:** H3AD-HUNT (`h3ad-sec.github.io/H3AD-HUNT/`)
- **Tagline:** Hunt smarter. Miss nothing.

HYPOS is a **sub-tool under H3AD-HUNT** (same pattern as VERDIKT is under H3AD-X). Nav reflects this — H3AD-HUNT has a dropdown containing HYPOS.

---

## What HYPOS does

**Input:** MITRE ATT&CK technique ID (T1003), group name (APT28), malware (Mimikatz), tool (Cobalt Strike), or campaign name.

**Output:** Structured hunt hypothesis cards containing:
- Hypothesis statement (IF/THEN format)
- Data sources & components
- Platforms
- Detection focus (from MITRE)
- Sub-techniques (clickable)
- ATT&CK link

For actor inputs (group/malware/tool/campaign), results are grouped by tactic with collapsible sections.

---

## Data approach

The app fetches the **MITRE ATT&CK STIX bundle** live from GitHub:
```
https://raw.githubusercontent.com/mitre/cti/master/enterprise-attack/enterprise-attack.json
```

Flow:
1. On load, check `localStorage` for cached processed data (7-day TTL, key `hypos_v2`)
2. Try `./data/attack.json` (pre-built static file, if present)
3. Fall back to live STIX fetch from GitHub raw

After fetching (~27MB raw, ~3-5MB gzip transfer), processes in-browser → compact object, caches to `localStorage`.

### Build script (when Node.js available)

`scripts/build-data.js` — fetches STIX, processes, writes `data/attack.json`. Commit that file to the repo to skip the live fetch entirely.

```bash
node scripts/build-data.js
```

## Key implementation details

### data-loader.js

`loadData(onProgress)` — async, calls `onProgress(state, msg)` where `state` is `'loading'` or `'ready'`.

`processBundle(bundle)` — pure fn. Extracts: techniques (with `sentence` = first sentence of description), groups, malware, tools, campaigns. Resolves `subtechnique-of` relationships (sets `pid`, `subs`). Resolves `uses` relationships (populates `actor.techs`).

Technique fields: `id, name, desc, sentence, tactics, platforms, ds, detect, analytics, sub, pid, subs, url`

`analytics`: `{ "Source: Component": "analytic text" }` — extracted from `detects` relationship descriptions in STIX.

Actor fields: `type, id, name, aliases, desc, url, techs`

Cache key: `hypos_v5` in localStorage. TTL: 7 days. Bump version to invalidate all cached data when schema changes.

### lookup.js

`detectQueryType(q)` — regex-based:
- `T1234` or `T1234.567` → `technique-id`
- `G0007` → `group-id`
- `S0002` → `software-id`
- `C0001` → `campaign-id`
- else → `name`

`lookup(q)` returns `{ type, actor?, items, query }` where `type` matches actor type or `'technique'` or `'not-found'`.

`suggest(q, limit=12)` — returns `[{ id, name, type }]`. Priority: exact ID prefix → name prefix → name contains.

### hypothesis.js

`generateHypothesis(technique)` — builds hypothesis statement from `sentence` + tactic goal template. Detection from MITRE `detect` field (first sentence) or data source fallback.

`groupByTactic(hypotheses)` — returns `[{ tactic, items }]` in canonical ATT&CK tactic order.

### hyp-db.js

Loads `data/hyp-db.json` with curated hypotheses. Exports:
- `getCurated(techId)` — returns curated array or null
- `getCuratedStats()` — `{ techniques, hypotheses }` counts from full DB (not just visible techniques)
- `getRelated(techId)` — technique IDs sharing tools/actors in curated DB
- `lookupByTag(query)` — fuzzy match on tool/actor tag index
- `suggestTags(query, limit)` — autocomplete suggestions for curated tool/actor names

### ui.js

All HTML generation uses `escapeHtml()` and `escapeAttr()` on user-derived and STIX content.

Default view: `renderAllResults()` — renders 14-column ATT&CK matrix with stats bar.

`renderResults(lookupResult)` — dispatches to `renderTechniqueResults`, `renderActorResults`, or `renderAllResults`.

`renderCard(h)` — auto-detects curated techniques and calls `renderCuratedCard` with full hypothesis detail, detection logic, mitigations, export buttons, related chips.

`buildDsComponentChips(ds, analytics)` — clickable chips that trigger DATA SOURCE filter; `.has-analytic` class when MITRE analytic exists.

`buildAnalyticsSection(ds, analytics)` — renders "DETECTION ANALYTICS · MITRE ATT&CK" block.

`window.__exportHyp(techId, format, btn)` — MD or JSON clipboard export for curated cards.

`setDataStatus(state, text)` — updates hero status dot. States: `loading` (yellow pulse), `ready` (green), `error` (red).

Terminal loading: `showLoading` → `appendTerminalLine` → `finalizeTerminal`.

## Conventions

- No framework — vanilla JS ES modules. Single HTML + linked JS/CSS.
- No external CSS — all styles in `css/style.css` with CSS variables.
- No comments in committed code.
- `escapeHtml()` on all STIX content going into `innerHTML`.
- `escapeAttr()` on all values going into HTML attributes.
- `window.__hypSearch(id)` — global search trigger for inline onclick in rendered cards.
- `window.__hyposLookup` — exposes `{ detectQueryType }` for ui.js badge updates.
- URL param `?q=T1003` — loads and runs search on page init.
- localStorage cache key `hypos_v5` — bump version string to invalidate all cached data.
- `window.__exportHyp(techId, format, btn)` — clipboard export for curated cards (MD or JSON).
- `/` keyboard shortcut focuses search bar (unless in input/textarea/select).
- DATA SOURCE filter row auto-hides if no data sources are present in loaded data.

## Testing checklist

1. Open page → terminal shows loading lines → `data-status` dot turns green on completion
2. Search `T1003` → parent card + sub-technique section (T1003.001 through .008)
3. Search `T1003.001` → single card, parent link in footer
4. Search `APT28` → actor header (GROUP badge, aliases, tech count) + tactic groups
5. Search `Mimikatz` → malware header (MALWARE badge) + techniques
6. Click example chips on welcome screen → triggers search
7. Click sub-technique chip on parent card → searches that sub-technique
8. Click parent link on sub-technique card → searches parent
9. Autocomplete: type `T10` → dropdown shows technique IDs
10. Autocomplete: type `lazaru` → shows Lazarus Group
11. Arrow keys navigate autocomplete; Enter confirms; Escape closes
12. Theme toggle → logo switches, matrix color switches
13. `?q=T1059` URL param → auto-runs search on load
14. Cache: reload page after first load → loads from cache (no STIX download)
